How to read this manual / 本マニュアルの読み方

This manual has no screenshots. The real UAT environment could not be captured for images at the time of writing, so each screen is described in text — purpose, key actions, and cautions — plus a screen-flow table at the end showing how screens link to one another. This is a recorded, deliberate difference from the original plan; see COMPROMISES.md entry F-1.

本マニュアルはスクリーンショットを含みません。執筆時点で実UAT環境から画像取得ができなかったため、各画面はテキスト（目的・主要操作・注意）で説明し、末尾に画面遷移表を付けています。裁定F-1として妥協レジスタに記録済みです。

The 5 verdict colors / 判定5色

Every demand line that has been evaluated for coverage gets one verdict. The five verdicts and their colors are fixed and never merged:

VerdictColorMeaning
CoveredGreenDirectly covered by matching stock/plan.
Covered (via substitute)Green outlineCovered only because an approved substitute product is used.
PendingAmber (light)Awaiting a substitution approval decision.
UncoveredAmber (solid)Not covered today, but recoverable with action (e.g. an order).
UnrecoverableRedCannot be covered in time by any known means. Red is reserved exclusively for Unrecoverable — no other state ever uses red.

A sixth grey state, Not evaluated, appears on lines the engine has not yet scored; it is excluded from the coverage-rate denominator (see Home).

評価済みの需要明細には必ず1つの判定が付きます。5色は固定で混同されません。赤は Unrecoverable 専用です。未評価（灰色）はカバレッジ率の分母から除外されます。

Overdue / 期限超過

A requirement or receipt is overdue when its Required-on-Site (ROS) month is earlier than the current calendar month. Overdue rows carry a red overdue-chip badge distinct from the Unrecoverable verdict chip.

要求/入荷の必要着地月（ROS）が現在の暦月より前の場合「overdue」です。赤い overdue-chip バッジで表示されます（Unrecoverable の判定チップとは別物）。

“Unknown” is not zero / unknown ≠ 0

Where a quantity, date, or count shows — or “unknown”, it means the platform has no data — it is not the same as a value of zero. Do not treat a dash as “nothing needed”; treat it as “not yet known” and investigate the source (e.g. missing weight_kg, missing coverage evaluation).

数量・日付・件数が「—」や unknown と表示される場合、データが存在しないことを意味し、ゼロとは異なります。「何も必要ない」ではなく「まだ分からない」として扱い、原因（weight_kg 未設定、未評価など）を確認してください。

Known limitations / 既知の制限

C-03R — Company inventory rows fed from the Oracle source system (source_system == "oracle") cannot be manually edited or deleted from the Company Inventory screen; such attempts are rejected (HTTP 409). Manual add/edit/delete only applies to non-Oracle rows, until a live Oracle feed replaces this manual workflow.
自社在庫（Company Inventory）の Oracle 由来行は手動編集・削除不可（409で拒否）。手動メンテはOracle以外の行のみです。
C-15R — The Administration screens are gated by login but not by an admin-only role check at this stage; any signed-in user who navigates to /admin can reach them. Do not rely on the UI alone to keep non-admin users out — this is a recorded, temporary gap (role-gating is planned for a later phase).
管理画面（Administration）はログイン必須ですが、現段階では管理者ロールの強制チェックが未適用です。ログイン済みの利用者であれば /admin に到達できます。将来フェーズでロールゲートを導入予定の既知の制限です。

Login / ログイン

Note: this UAT environment uses shared demo credentials and resets to demo state on each redeploy.

Purpose

Authenticate to receive a token used by all subsequent API calls. There is no self-service signup; accounts are provisioned by the platform (seed data in dev/UAT).

Key actions

Enter email and password, submit. On success you land on Home. Use the rail's “Sign out” to clear your session client-side (there is no server session to invalidate).

Dev / UAT credentials (seed data only — never use in production):
Admin: admin@octg.dev / octg-dev
Planner (SCEU Norway BU): planner@octg.dev / octg-dev

Cautions

A wrong password shows an inline error and keeps the form filled in. The token is stored in the browser only (localStorage) — closing all tabs does not end the session automatically.

Home / ホーム

Purpose

Landing dashboard after login. Summarizes customers, wells, coverage rate, pending approvals, recent demand changes, and wells needing attention.

Key actions

Click a well name to open its Well Workspace. Click “See all” links to jump to Demand or Coverage. Refresh the freshness indicator to re-pull KPI data.

Cautions

Coverage rate excludes not-yet-evaluated lines from its denominator; the not-evaluated count is shown alongside so it is never silently hidden. The pending-approvals card is a union of two sources (substitution approval requests and verdicts that are themselves “Pending”) — each row is labeled with its source.

Demand Import / 需要インポート

Purpose

Upload a spreadsheet of demand lines for a well/customer, preview validation results, then apply or discard the import.

Key actions

Choose file → upload → review the preview (row-level errors are listed, valid rows are highlighted) → Apply to commit, or Discard to cancel.

Cautions

Applying an import creates a new DemandRevision — it does not silently overwrite previous data; history remains visible in Demand List. Row errors block only the affected rows unless the whole file fails validation.

Demand List / 需要一覧

Purpose

Browse demand lines across wells with filters, and see the demand revision history.

Key actions

Filter by customer/well/product; sort columns; click a line to jump into its Well Workspace context.

Cautions

Filters are reflected in the URL (shareable/bookmarkable) and are not lost on refresh.

Well Workspace / 井戸ワークスペース

Purpose

Single-well detail: demand lines, their verdicts, and revision history for that well.

Key actions

Review each line's verdict chip; follow links into Coverage or Substitution for lines needing action.

Cautions

A well's status (Planned / Budgeted / Confirmed) affects which demand can still be edited — check the status badge before assuming a line is actionable.

Coverage Workspace / カバレッジ

Purpose

The evaluation engine's output: for every demand line, whether it is covered, and by what (own stock, substitute, or not at all).

Key actions

Filter by verdict/customer/well; drill into Unrecoverable or Uncovered lines to decide next steps (order, substitute, escalate).

Cautions

Red is reserved for Unrecoverable only — never assume amber and red mean the same severity. This table keeps horizontal scroll on narrow screens rather than collapsing into cards, so all verdict columns stay visible together.

Substitution Workspace / 代替品

Purpose

Propose and manage substitute products for demand lines that cannot be covered by the exact requested product.

Key actions

Select a candidate substitute, submit for approval. Approved substitutions turn the line's verdict into “Covered (via substitute)”.

Cautions

A submitted substitution is not applied until approved in Approval Queue — the demand line stays in its prior verdict (often Pending) until then.

Approval Queue / 承認キュー

Purpose

Decide (approve/reject) pending substitution requests.

Key actions

Review the proposed substitute against the original product spec, then Approve or Reject with a confirm step (destructive-feeling actions require a second click to arm).

Cautions

Rejecting does not delete the underlying demand line — it returns the line to its prior verdict so it can be re-evaluated or resubmitted.

Sharing Analysis / シェアリング分析

Purpose

Shows how a shared/pooled inventory position is allocated across multiple wells or customers.

Key actions

Review allocation splits; identify wells whose share depends on a contested or scarce item.

Cautions

Allocation numbers reflect the current evaluation snapshot — re-run/refresh after any demand or inventory change before relying on the split.

MRP Summary / MRPサマリー

Purpose

Aggregate material-requirements-planning view across products/time buckets.

Key actions

Scan for deficits by product/month; drill into MRP By Item for detail.

Cautions

This table keeps horizontal scroll on narrow screens (never collapses to cards) so month columns stay aligned.

MRP By Item / 品目別MRP

Purpose

Per-item ledger of booked vs. recommended receipts against requirements over time.

Key actions

Distinguish booked receipts (blue) from recommended receipts (amber italic) — booked means an order already exists; recommended is the engine's suggestion, not yet ordered.

Cautions

Never read a recommended receipt as if material is already on order. This table keeps horizontal scroll and does not collapse into cards.

Order Requirements (MOR) / 発注要求

Purpose

Material Order Requirements: a strip view per product showing monthly ok/deficit cells with deadline, runout, and safety-stock markers.

Key actions

Read the strip left-to-right by month; a deficit cell is highlighted red-tinted. An order-deadline that falls before the first visible strip month is shown as a header chip rather than a cell.

Cautions

The overdue-chip (red, row-level) and the overdue-strip-chip (amber, header-level) are visually distinct on purpose — do not conflate them. This table keeps horizontal scroll and does not collapse into cards.

Surplus / 余剰在庫

Purpose

Identify inventory positions that exceed near-term demand (candidates for redeployment or de-risking).

Key actions

Review surplus-dot severity (ok/warn/bad, never merged) per item; consider proposing a substitution/transfer elsewhere.

Cautions

A surplus figure is a snapshot; it does not account for demand not yet imported into the system.

Executive Dashboard / 経営ダッシュボード

Purpose

High-level, cross-cutting metrics for leadership: coverage health, MT (metric-tonnage) headline figures, scope checks.

Key actions

Use as a starting point before drilling into Coverage, MRP, or Surplus for root cause.

Cautions

MT headline figures depend on Product.weight_kg being populated; products missing this field are excluded from MT totals (a recorded compromise — see COMPROMISES.md C-06R).

Scenarios / シナリオ

Purpose

Draft what-if overrides (e.g. hypothetical demand or inventory changes) and preview their effect before applying them to live data.

Key actions

Create a scenario, add overrides, preview the delta (changed rows are highlighted), then Apply (draft → applied) when satisfied, or discard.

Cautions

An applied scenario is not reversible from the UI — review the preview carefully first. Draft scenarios never affect other users' live views.

Product Catalog / 製品カタログ

Purpose

Browse the master product list (specs, substitution groups, weight_kg where known).

Key actions

Search/filter by spec fields; use this to confirm a substitute candidate's compatibility before proposing it in Substitution Workspace.

Cautions

Products with a blank weight_kg cannot contribute to MT-based figures elsewhere in the platform.

Company Inventory / 自社在庫

Purpose

On-hand company-owned stock by product/location.

Key actions

Add/edit/delete manual rows (non-Oracle only). Oracle-sourced rows are read-only here.

Cautions

C-03R: attempting to edit or delete an Oracle-sourced row returns an error (409) — this is expected, not a bug, until a live Oracle feed replaces manual entry.

Customer-Owned Inventory / 顧客所有在庫

Purpose

Track inventory owned by a customer but staged/available for a well (uploaded per customer via spreadsheet).

Key actions

Select a customer, upload a position file; review row-level upload errors before they affect coverage evaluation.

Cautions

No customer selected means no data shown — this is a normal empty state, not an error.

Administration / 管理

Purpose

Manage master data: business units, customers, products, users, and related reference tables.

Key actions

Add/edit reference rows via the admin tables; changes take effect immediately across the platform.

Cautions

C-15R: reachable by any signed-in user, not just admins, at this stage (see “Known limitations” above). Be careful who you share credentials with in the interim.
